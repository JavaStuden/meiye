## 发现与修复

| 问题 | 修复与复测结果 |
| --- | --- |
| 非法开播日期导致未处理异常 | 3种非法日期改为400；旧标题、模式、排期不被覆盖；专项及最终回归通过 |
| 页面显示旧价，后台改价后按新金额直接创建订单 | 商品列表和选购前读最新数据；提交显示单价进行冲突校验；旧价返回409、不新增订单，保留填写内容并引导重选 |
| 回放暂停后被8秒轮询重新弹出开始层遮挡 | 暂停保留视频画面和控制条；拖到45秒、1.25倍速、暂停超过轮询周期后仍保持原状态 |
| 播放完成提示被轮询覆盖 | 本地120秒视频到片尾后保持“播放完成”；重新播放入口保留 |
| 后台切模式、评论开关后已打开观看页不更新 | 模式变化自动刷新；评论禁用/启用、公告、标题等按轮询同步；浏览器两次开关均验证 |
| 伪直播排期结束但标签仍为待开播 | 状态标签按排期计算；API测试覆盖前/中/后，最终JAR浏览器确认已结束 |
| 编辑商品时点击新增仍保留旧商品ID | 新增链接移除edit参数；最终JAR浏览器确认空表单且隐藏ID数量为0，避免覆盖旧商品 |
| 商品校验失败跳到JSON页、保存成功缺少反馈 | 改为保留输入的错误提示与一次性成功通知；浏览器确认错误划线价提示、原输入保留 |
| Windows启动脚本把JDK 21误判为不支持 | 完整收集Java版本输出后检查退出码与版本号，避免管道提前关闭影响结果；修复后通过脚本实际启动成功 |

同时修正了两个测试自身问题：真实机器变慢使“两次请求必在500毫秒内”的假设不成立，现改用固定时钟和独立边界测试；HTML5页面不能交给严格XML XPath解析，新增链接改为对实际HTTP渲染结果断言。修复前失败记录保留在工作区，最终套件没有删除、跳过或放宽业务断言。
